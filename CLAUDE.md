# GOSTwriter: как устроено

Документ для разработки. README — витрина для пользователя: что умеет и как запустить. Внутри кода и в этом документе проект по-прежнему зовётся writer: так называются ключи оболочки, протокол плагина office и формат книги в публикации (`urn:writer:book`), их не переименовываем.

Книга в браузере, раскладка как в IDE. Слева структура книги по ГОСТ 7.32: титульный лист, введение, разделы, заключение, свои блоки. Каждый блок — папка, в ней текст `.docx`, названный как блок. Справа ONLYOFFICE Docs — редактор как Word со встроенным редактором формул. Текст блока правится в левой половине и сохраняется прямо в его папку. Источник — книга или веб-страница — открывается рядом, в правой половине, на просмотр: из него цитируют в текст со сноской.

Панель слева разделена на области, как проводник VS Code: «Структура» — блоки книги, «Публикация» — собранная книга. Щелчок по заголовку области сворачивает и разворачивает её. Кнопка слева сверху скрывает панель целиком, под ней — «Расширения»: плагины, как в VS Code. Кнопки слева внизу — проверка орфографии и настройки книги. Ширину панели структуры и книги меняют, перетаскивая границу между панелями левой кнопкой мыши. Открытые файлы, свёрнутые блоки и области, скрытую панель и ширину панелей оболочка помнит: после обновления страницы всё как было.

## Запуск

1. `make init` — создаст `.env` из `.env.example`, `docker-compose.local.yml` и папки `deploy/book` и `deploy/fonts`, соберёт образ api, скачает ONLYOFFICE и запустит оба сервиса. В новый `.env` он сам пишет UID и GID того, кто запускает, и новый общий секрет api и office `OFFICE__JWT_SECRET`; готовый `.env` не трогает. Без секрета api не стартует. Папку с готовой книгой можно указать в `BOOK_DIR`.
2. Открыть `http://localhost:8020` (порт — `API_PORT`). Первый запуск office занимает около минуты: пока он собирает шрифты, редактор не откроется.

Дальше: `make compose-up`, `make compose-down`, `make compose-logs`, `make compose-ps`.

`RUN_MODE` в `.env` выбирает оверлей поверх `docker-compose.yml`:

- `dev` — код смонтирован в контейнер, api перезапускается при правке файлов;
- `prod` — код внутри образа.

Свои правки compose кладём в `docker-compose.local.yml`, его нет в git.

## Как устроено

- `office` — ONLYOFFICE Docs Community Edition (AGPL), готовый редактор. В нём оформление, таблицы, формулы (Вставка → Уравнение, ввод в LaTeX), сноски, оглавление, сохранение в DOCX и PDF.
- `api` — FastAPI. Отдаёт оболочку и связывает её с office по [Docs API](https://api.onlyoffice.com/docs/docs-api/get-started/basic-concepts/):
  - `service/book/` — книга на диске: `paths.py` — пути от корня книги без выхода за её пределы, `blocks.py` — блоки книги по порядку, `headings.py` — заголовки раздела и их нумерация, `changes.py` — новый блок, переименование и перестановка, `texts.py` — текст нового блока из шаблона, `materials.py` — ссылки на книги и копии страниц в папке источников блока, `document.py` — публикация по ГОСТ 7.32–2017 (docxcompose), `transfer.py` — экспорт и импорт: вся книга в скрытой части публикации, `trash.py` — корзина, `settings.py` — настройки книги;
  - `service/sources/` — источники цитат: `models.py` — данные книги и веб-страницы, `store.py` — `источники.json` и имя ссылки, `bookfile.py` — текст книги (PyMuPDF, у DJVU — `djvutxt` из djvulibre), `description.py` и `recognize.py` — данные книги из неё самой, `quotes.py` — цитата и её страницы, `web.py` и `web_copy.py` — веб-страница и её копия ([trafilatura](https://trafilatura.readthedocs.io/)), `styles.py` — оформление сносок;
  - `service/office/` — ONLYOFFICE: `formats.py` — что открывает редактор, `editor.py` — конфиг редактора, подписанный JWT, `callback.py` — приём сохранённого файла, `builder.py` — содержание собранной книги: номера страниц в нём проставляет office;
  - `service/library.py` — папки библиотеки для окна выбора книги;
  - `service/plugins.py` — плагины: список, включение в книге, хуки, файлы настроек, импорт .zip, см. «Расширения»;
  - `service/fonts.py` — шрифты для office: каких в нём нет, скачивает из Google Fonts, см. «Шрифты»;
  - `service/spelling.py` — подключение к MCP-серверу проверки орфографии;
  - `api/` — ручки по темам: блоки, материалы, источники, цитата, библиотека, настройки, проверка орфографии, office, импорт книги. Ошибки сервисов (нет файла, такой уже есть) `main.py` превращает в понятный ответ для оболочки;
  - `web/` — оболочка без сборки: `index.html`, стили в `css/`, модули в `js/` — структура книги и перетаскивание блоков, два редактора (`api.js` с office), связь с плагином, окна выбора источника, данных источника и настроек, разделители между панелями, панель «Расширения» (`extensions.js`);
  - `plugin/` — плагин «Цитата» для обоих редакторов, см. «Цитата из книги».

Текст блока office скачивает у api по ссылке из конфига редактора. Сохранённый он присылает ссылкой на callback, и api записывает файл в папку блока:

- Ctrl+S — сразу (статус 6);
- закрыли файл — примерно через 10 секунд (статус 2).

Если блок переименовали или переставили, пока его текст был открыт, правки api запишет по новому пути. Если блок унесли в корзину — в его копию в корзине, даже когда на его месте уже другой блок с тем же путём, например после импорта книги. Для этого в адресе callback — время, когда текст открыли.

## Книга на диске

```
deploy/book/                         или своя папка из BOOK_DIR
├── шаблон-главы.docx                стили, поля, колонтитулы нового блока; без него — пустой A4 на русском
├── источники.json                   данные источников для ссылок: книг и веб-страниц
├── настройки.json                   настройки книги из оболочки: оформление ссылок, MCP-сервер
├── плагины.json                     какие плагины включены в книге и их настройки, см. «Расширения»
├── .плагины/                        файлы из настроек плагинов, например образец оформления
├── Публикация.docx                  собранная книга, в ней же вся книга для импорта, см. «Публикация»
├── .корзина/                        удалённые блоки, см. ниже
├── 01-Титульный лист/
│   ├── .вид                         вид блока: title_page
│   └── Титульный лист.docx
├── 02-Введение/
│   ├── .вид                         introduction
│   └── Введение.docx                «ВВЕДЕНИЕ» и текст — правится в редакторе
├── 03-Методы испытаний двигателей/  раздел: файла .вид нет
│   ├── Методы испытаний двигателей.docx    «1 Методы…», «1.1 Стендовые испытания», «1.1.1 …»
│   └── источники/
│       ├── Ландау Л. Д. Механика.djvu → ~/Книги/Физика/landau.djvu    ссылка на книгу — на просмотр
│       └── Соколов А. Статья о весах моделей.html                       копия веб-страницы — на просмотр
└── 04-Заключение/
```

Блок книги — папка в её корне. Порядок блоков задаёт номер в начале имени папки, вид блока — скрытый файл `.вид` в ней: `introduction` — введение, `conclusion` — заключение, `title_page` — титульный лист, `custom` — свой блок; без файла это раздел. Текст блока назван как он сам, без номера: `02-Введение/Введение.docx`. В дереве файла текста нет — щелчок по названию блока открывает его текст слева. Источники блока лежат в его папке `источники/`, в дереве это узел «Источники (N)».

«+» у заголовка «Структура» открывает меню: Титульный лист, Введение, Раздел, Заключение, Свой блок. У раздела и своего блока спрашивается название, остальные называются сами. Введение, заключение и титульный лист бывают по одному на книгу: когда такой уже есть, пункт меню неактивен. Новый блок встаёт на своё место по ГОСТ: титульный лист — в начало, введение — перед разделами, раздел — после разделов, заключение — за ними, свой блок — в конец. Его текст создаётся из шаблона и сразу открывается слева, в начале текста — заголовок: «1 Методы испытаний двигателей» у раздела, «ВВЕДЕНИЕ» по центру прописными у введения, заключения и своего блока. У титульного листа заголовка нет.

Блоки переставляют, перетаскивая мышью в дереве: полоса показывает, куда блок встанет. Номера в именах папок и номера разделов пересчитываются сами.

Разделы нумеруются по порядку, 1, 2, 3, — другие блоки в счёт не идут. Подразделы, пункты и подпункты — заголовки в тексте раздела (стили «Заголовок 2»…«Заголовок 4»), в дереве они под разделом. Под мышью у раздела «+» добавляет подраздел в конец раздела, у подраздела — пункт в конец подраздела, у пункта — подпункт; у подпункта «+» нет. Спрашивается только название: заголовок сразу встаёт в текст, под ним пустой абзац для текста. Щелчок по заголовку в дереве ставит к нему курсор.

Номера заголовков ставит сам редактор — это нумерация Word, привязанная к стилям заголовков: «1.1 Стендовые испытания», «1.1.1 …», «1.1.1.1 …». Подраздел, вставленный, удалённый или перенесённый прямо в тексте, перенумерует соседей, а дерево покажет его через секунду после того, как курсор замер. Номер раздела в тексте плагин сверяет с деревом, когда текст открывается: после перетаскивания он поправится сам. Вручную номер не меняют.

«✎» у раздела и своего блока переименовывает папку и текст. Заголовок в тексте поправит плагин, поэтому после переименования текст блока открывается. Заголовок блока меняют только так: поправленный прямо в тексте вернётся к названию из дерева, когда текст откроют снова. Переименовать и перетащить можно и открытый блок: ключ документа в office не зависит от пути, и правки остаются в редакторе.

Скрепка подключает книгу с диска или веб-страницу (см. «Веб-страница»). Книгу выбираешь в папках библиотеки, и открывается форма с данными книги для ссылок: авторы, заглавие, издание, город, издательство, год, сдвиг страниц. Api находит их в самой книге:

- у русских книг — описание на обороте титула (УДК, ББК, авторский знак, ISBN);
- у английских — свойства PDF (Title, Author), город и издательство дописывают руками;
- у сканов без текста и прочего — только имя файла.

Проверяешь, правишь, «Подключить» — и в папке источников блока появляется ссылка на книгу (symlink) с именем «первый автор + заглавие»: `Ангелакос Д. Антипаттерны PostgreSQL и как их избежать.pdf`. Форма показывает это имя и пример сноски. Данные ложатся в `источники.json` в корне книги, одна запись на книгу для всех блоков. «✎» у книги в дереве открывает ту же форму: исправленные данные сохраняются, ссылка получает новое имя.

Сдвиг страниц — на сколько номер страницы в файле больше печатного; по нему в сноске будет печатная страница. Api считает сдвиг по меткам страниц PDF или по номерам в колонтитулах, у сканов без текста его ставят руками.

Сама книга не копируется и остаётся на месте; одну книгу можно подключить к нескольким блокам. Если книгу перенести, ссылка в блоке останется, но открыться не сможет. Открываются PDF, DJVU, EPUB, FB2, DOCX, DOC, ODT, RTF, TXT, MD, HTML, XLSX, PPTX — всё, кроме текста блока, на просмотр. Справа книгу закрывает крестик в заголовке редактора.

«✕» у книги убирает её из блока. Сначала оболочка открывает текст этого блока, и плагин считает в нём сноски на книгу. Окно подтверждения говорит, сколько их: они удалятся вместе с книгой, текст цитат останется. Удаляется только ссылка, сама книга остаётся на диске. Копия веб-страницы или файл, положенный в блок целиком, удаляются из его папки — об этом окно тоже предупреждает.

«✕» у блока уносит его в корзину со всем, что в нём: текстом со всеми подразделами, ссылками на книги и копиями веб-страниц. Корзина — скрытая папка `.корзина` в папке книги, дерево её не показывает. Папка блока получает там имя из времени удаления и пути блока: `2026-11-06 10-15-03 03-Методы испытаний двигателей`. Вернуть блок — перенести папку обратно в книгу с прежним именем (в файловом менеджере скрытые файлы показывает Ctrl+H), очистить корзину — удалить папку. Сами книги по ссылкам остаются на диске.

Файлы и ссылки в папки блоков можно класть и снаружи: дерево обновляется при возврате на вкладку.

## Публикация

Галка справа в заголовке области «Публикация» собирает `Публикация.docx` в корне книги. Оформление — по ГОСТ 7.32–2017:

- первая страница — титульный лист, если он есть: номер на ней не печатается, но страница в счёте;
- дальше «СОДЕРЖАНИЕ» на своей странице: блоки, разделы, подразделы и пункты с номерами страниц, отточие до номера. Подпункты в содержание не входят;
- дальше тексты блоков по порядку, каждый с новой страницы, при любых требованиях к оформлению. Пустые абзацы в конце текста в публикацию не идут: иначе они могли бы занять свою пустую страницу. Заголовки уже в текстах, номера разделов в публикации идут подряд, по ГОСТ без точки в конце: «2.1 Стендовые испытания»;
- таблица между страницами не рвётся: не уместилась внизу страницы — переходит на следующую целиком, вместе с подписью над ней. Таблица длиннее страницы начинается сразу под подписью и продолжается на следующих: держать её целиком негде. Длинную или нет, api оценивает по тексту и картинкам в ячейках, целиком держит таблицу до ¾ страницы. Текст переходит со страницы на страницу как обычно;
- в конце, тоже с новой страницы, «СПИСОК ИСПОЛЬЗОВАННЫХ ИСТОЧНИКОВ»: все книги и веб-страницы, подключённые к блокам, и все, на которые стоят сноски. Записи — по правилу оформления из настроек, без страниц, по алфавиту: сначала русские, потом иностранные. Файл, положенный в папку источников снаружи, без данных из формы «✎» в список не попадает;
- номер страницы — внизу по центру, без точки.

Содержание всегда идёт сразу за титульным листом. Реферат и другие свои блоки, которые по ГОСТ стоят перед содержанием, пока оказываются после него.

Строки содержания с номерами страниц заполняет сам ONLYOFFICE: его сервис Document Builder раскладывает книгу по страницам. На 400 страниц уходит около 15 секунд. Стили, размер страницы, поля и колонтитулы публикация берёт из шаблона; если в шаблоне свой нижний колонтитул, номер страницы туда не добавляется.

Публикация открывается справа на просмотр, её строка — в области «Публикация». Галка собирает её заново, стрелка у строки скачивает (см. «Экспорт и импорт»), «✕» удаляет. Сборка берёт тексты, сохранённые на диске: перед ней — Ctrl+S в открытом тексте.

## Экспорт и импорт

Экспорт — сама публикация. Собирая её, api кладёт в скрытую часть документа (customXml) всю папку книги как есть: тексты блоков, копии веб-страниц, данные источников, настройки книги и плагинов. Корзины там нет. Книги из библиотеки внутрь не попадают, только ссылки на них с путём. Стрелка вниз у строки публикации скачивает её с датой и временем в имени: `Публикация 2026-11-09 14-30.docx`. Это обычный документ Word: его можно открыть, отправить, а потом импортировать обратно.

Стрелка вверх в заголовке области «Публикация» импортирует книгу из такого файла. Текущая книга целиком уходит в корзину, у всех её частей там одно время в имени: `2026-11-09 14-35-02 02-Методы испытаний`, `2026-11-09 14-35-02 источники.json`. На её место встаёт книга из файла, а публикацией становится сам файл. Текст, открытый в редакторе в момент импорта, office сохранит в его копию в корзине, а не поверх новой книги.

- Импортируется только публикация, собранная в writer. В документе Word без скрытой части книги нет: импорт ответит ошибкой, книга останется как была.
- Книгу импорт берёт из скрытой части, а не из текста публикации: правки, внесённые в файл в Word, в книгу не вернутся.
- Ссылки на книги работают на том же рабочем месте: книга откроется, если лежит по тому же пути. На другом компьютере ссылка останется в блоке, книга — в списке источников, «✕» найдёт её сноски, но открыть её можно, только положив по тому же пути.
- Пересохранение в LibreOffice скрытая часть переживает, это проверено. В Word не проверяли.

## Расширения

Плагины writer, как расширения VS Code. Кнопка под «скрыть панель» показывает вместо структуры книги панель «Расширения», повторный щелчок скрывает её. В панели — установленные плагины: название, версия, что делает, галка «Включён в этой книге» и настройки плагина. «+» в заголовке панели импортирует плагин из архива .zip, «Удалить» уносит его папку в корзину плагинов.

Плагин — папка в `plugins/` (`PLUGINS_DIR` в `.env`). В ней манифест `plugin.json` и, если плагину есть что делать в api, `api.py` с хуками ядра. Архив для импорта — эта папка целиком: `zip -r article-style.zip article-style`. Импорт той же папки заменяет плагин новой версией, старая уходит в корзину. Новый плагин работает сразу, без перезапуска. Как устроены манифест и хуки — в [PLUGINS.md](PLUGINS.md).

Какие плагины включены в книге и как настроены, лежит в `плагины.json` в корне книги. Плагина там нет — он включён, настройки у него по умолчанию. Плагин — это код, который выполняет api, поэтому импортировать стоит только плагины, которым доверяешь.

### Научная статья

Оформление текста стилями Word: шрифт и интервалы, поля, заголовки, таблица, рисунок и подписи к нему и к таблице, формула с номером справа, сноски, УДК, название, авторы, аннотация. Требования выбираются в панели:

- научная статья — Times New Roman 14 пт, интервал 1,5, отступ 1,25 см, по ширине, поля 20 мм;
- отчёт по ГОСТ 7.32–2017 — то же, но поля 30/15/20/20 мм, подписи 14 пт. Сверено с разделом 6 стандарта: полужирные только разделы и подразделы, пункты и подпункты обычным шрифтом; «Рисунок 1 — Название» под рисунком по центру, «Таблица 1 — Название» над таблицей слева, обе подписи через один интервал; сноска с абзацного отступа; выше и ниже формулы — свободная строка. Где стандарт оставляет выбор (кегль не меньше 12 пт, шрифт в таблице можно мельче), выбрано 14 пт для текста и 12 пт в таблице, 10 пт в сносках. Эти же правила взяты и для статьи;
- APA, 7-е издание — Times New Roman 12 пт через два интервала, отступ 1,27 см, по левому краю, поля 2,54 см. Заголовки без номеров: первого уровня по центру, ниже слева. «Figure 1» и «Table 1» — полужирным над рисунком и таблицей, название — следующей строкой курсивом, у таблицы линии только сверху, под шапкой и снизу. Сноска 10 пт, одинарный интервал, с отступа. Аннотация без отступа, строка «Keywords:» — обычным абзацем с отступом. Заголовок 4-го уровня по APA пишется в строку с текстом и с точкой в конце; стиль Word так не умеет, поэтому он отдельной строкой.

По выбранным требованиям создаются тексты новых блоков, и по ним же собирается публикация: стили берутся из шаблона плагина, поэтому и старые тексты в публикации выглядят по требованиям. Сами написанные тексты в редакторе не меняются. Свой `шаблон-главы.docx` в книге работает, когда плагин выключен.

Стили видны в галерее стилей редактора: «Рисунок», «Подпись таблицы», «Формула», «Аннотация», «Авторы», «УДК». Подпись рисунка вставляет сам редактор: Ссылки → Название, номер он считает сам. Новая таблица и сноска сразу получают оформление из шаблона. Формула: Tab, формула, Tab, «(1)» — в стиле «Формула» формула встанет по центру, номер у правого поля.

Публикация и по APA собирается с содержанием и списком источников по ГОСТ, а в дереве у разделов остаются номера: плагин меняет оформление, но не состав книги. Шаблоны собирает `plugins/article-style/templates.py`.

### Оформление по образцу

Шаблон по образцу — PDF или документу Word, оформленному как надо: статье из журнала, работе по методичке. Плагин читает в образце лист и поля, шрифт, кегль, интервал, абзацный отступ, выравнивание, заголовки по уровням, подписи рисунков и таблиц, сноски, номер страницы, строки содержания и записи списка источников. По ним он собирает пустой документ со стилями — такими же, как в «Научной статье», и с теми же именами. Чего в образце нет, берётся от основного текста.

Образец загружают в карточке плагина в «Расширениях»: «Загрузить…», потом «Заменить…» или «Убрать». Он лежит в книге, в `.плагины/sample-style/`, поэтому переезжает вместе с книгой при экспорте. Разбор занимает секунды. Карточка показывает, что прочитано: «Текст: Times New Roman, 14 пт, интервал 1,5, отступ 1,25 см, по ширине», и чего не нашлось. Если прочитано неверно, стиль правят в редакторе или загружают другой образец.

Шаблон книги даёт первый включённый плагин, поэтому «Научную статью» в книге выключают. Если она включена, после загрузки образца панель об этом скажет.

Как читается образец:

- из документа Word — стили и оформление прямо в тексте, как их складывает сам Word. Значения точные;
- из PDF — по строкам: шрифт и кегль основного текста, где начинаются и кончаются его строки, шаг между ними. Поля точны до миллиметра, нижнее — до строки: его видно только на странице, которую абзац продолжает на следующей. Не видно — оно как верхнее, карточка об этом скажет. Заголовки — крупнее, жирнее или прописными либо с номером «1.1». Подписи, содержание и список источников узнаются по словам «Рисунок 1», «СОДЕРЖАНИЕ», «СПИСОК ЛИТЕРАТУРЫ». Liberation Serif и другие шрифты с размерами шрифтов Microsoft считаются заменой оригинала — в шаблон идёт Times New Roman. Читаются первые 40 страниц.

Скан без текста не читается. Образец в две колонки даёт шаблон в одну.

Шрифта из образца нет в office — api скачивает его из Google Fonts, см. «Шрифты». Шрифта нет и там, например Minion Pro, — образец не принимается, прежний остаётся, а ошибка называет шрифт.

## Шрифты

Шрифты, которых нет в office, api скачивает в папку шрифтов `FONTS_DIR` (по умолчанию `deploy/fonts`): TTF из Google Fonts, все начертания и алфавиты семейства. Compose монтирует эту папку и в office. Сторож в контейнере office (`deploy/office/fonts-watch.sh`) замечает новые файлы и пересобирает список шрифтов office. Пересборка перезапускает службы office: открытые тексты переподключаются сами примерно за полминуты. Чтобы новый шрифт появился в списке шрифтов редактора, страницу обновляют.

Times New Roman, Arial, Calibri и другие шрифты Microsoft в office уже есть. Свой шрифт, которого нет в Google Fonts, можно положить в папку шрифтов файлами `.ttf` или `.otf`, и office поставит его так же.

## Веб-страница

Скрепка у блока → адрес страницы в поле сверху → «Подключить страницу». Api скачивает страницу, trafilatura находит в ней текст статьи и данные: заглавие, авторов, сайт, год. Форма показывает их вместе с адресом и датой обращения — сегодняшней. Проверяешь, дописываешь, чего не нашлось (авторов Хабр, например, не указывает), «Подключить».

В папку блока ложится копия текста страницы, `.html`, с именем «первый автор + заглавие». Она открывается справа, как книга, и цитируют из неё так же. Меню, реклама и прочая обвязка сайта в копию не попадают. Копия хранит текст таким, каким он был в дату обращения. Наверху копии — адрес страницы, по нему её можно открыть в браузере.

Сноска по ГОСТ Р 7.0.5–2008 — без страниц, с адресом и датой обращения: `Соколов А. Статья о весах моделей [Электронный ресурс] // Хабр. – 2026. – URL: https://habr.com/ru/articles/1103668/ (дата обращения: 06.11.2026).`

Некоторые сайты отказывают программам: Википедия, например, отвечает 403. Тогда форма предупреждает, что страница не скачалась, и данные вписываешь сам. Копия получится только с адресом, а сноску на страницу ставит правый клик в копии → «Сноска на эту страницу».

Данные страницы лежат в `источники.json` по её адресу. Одну страницу можно подключить к нескольким блокам, «✎» правит данные для всех.

## Цитата из книги

Слева открыт текст блока, справа книга или копия веб-страницы.

1. Ставишь курсор в тексте там, где нужна цитата.
2. В книге выделяешь текст, правый клик → «Цитировать».
3. В текст встаёт «цитата» и сноска внизу страницы по правилу из настроек книги, пока это ГОСТ Р 7.0.5–2008: `Ангелакос Д. Антипаттерны PostgreSQL и как их избежать. – СПб. : Питер, 2026. – С. 101.` Курсор стоит за знаком сноски, можно сразу писать дальше.

Переносы строк и слов из вёрстки книги в цитате склеиваются, конечная точка уходит за кавычки: «…данных»¹. Страницу api уточняет сам: ищет начало и конец цитаты на текущей и соседних страницах, а цитата на двух страницах даёт «С. 101–102». В сноске печатный номер — номер страницы в файле минус сдвиг из формы «✎». У веб-страницы, EPUB и FB2 устойчивых страниц нет, сноска на них — без страниц.

В DJVU и PDF-сканах без текстового слоя просмотрщик ONLYOFFICE выделять текст не даёт. Там правый клик → «Сноска на эту страницу»: вставится одна сноска, текст цитаты пишешь сам.

Как устроено. Плагин `app/plugin` compose монтирует в office (`sdkjs-plugins/writer`), конфиг редактора подключает и запускает его в обоих редакторах. Что он делает в книге — `book.js`, в тексте блока — `chapter.js`, `spelling.js` и `outline.js`, с меню и событиями редактора и с оболочкой их связывает `plugin.js`. `outline.js` — заголовки раздела: плагин присылает их оболочке, когда курсор замер, и по её просьбе ставит новый заголовок, название и номер раздела. Сообщения со страницы в плагин через Docs API работают только в платной редакции ONLYOFFICE, поэтому плагин пишет оболочке в `window.top`: из книги — выделенный текст и номер страницы. Оболочка собирает у api цитату со сноской (`POST /api/book/quote`) и отправляет её в окно плагина текста. Файлы плагинов office отдаёт с кешем на год, поэтому api ставит в адрес плагина версию из хеша его файлов: после правки плагина браузер загрузит новый.

Текст сноски — поле Word (addin-поле), так же вставляет ссылки плагин Zotero из office. В поле невидимо лежат ключ источника — путь книги на диске или адрес страницы — и страницы файла: `ADDIN WRITER_CITATION {"source": …, "pages": [101, 102]}`. Поле переживает сохранение в DOCX. По ключу «✕» находит сноски на источник, даже если его данные с тех пор поправили. Сноски, вставленные до полей, плагин узнаёт по началу текста: авторам и заглавию.

## Проверка орфографии

Встроенная проверка ONLYOFFICE подчёркивает слова с ошибками и предлагает замену по правому клику. Новые блоки создаются на русском языке, поэтому она проверяет их по русскому словарю. У старого текста на английском язык меняют в строке состояния редактора: выделить весь текст, нажать на язык и выбрать «Русский».

Проверку внешним сервисом подключают через MCP-сервер. Кнопка слева внизу над настройками открывает окно: адрес сервера → «Подключить». Api подключается к серверу и показывает его инструменты; адрес сохраняется в настройках книги, только если сервер ответил. Пустой адрес отключает проверку.

Адрес сервер должен видеть api из своего контейнера: `localhost` там — сам контейнер. Сервер в Docker — по имени сервиса в той же сети compose. Сервер на этом же компьютере — `host.docker.internal`, но только если файрвол хоста пускает подключения из Docker. С ufw, например: `sudo ufw allow from 192.168.208.0/20 to any port 9000`, где подсеть — сеть compose (`docker network inspect writer_default`).

В тексте блока правый клик → «Проверить орфографию» (выделенное) или «Проверить орфографию всего текста». Сама проверка пока заглушка: текст доходит до api, api подключается к MCP-серверу и отвечает, что проверки ещё нет, сколько знаков дошло и какие у сервера инструменты. Какой инструмент звать и как показывать исправления, решим, когда выберем сервер.

## Настройки

Значения лежат в `app/settings/config.toml`, значений по умолчанию в коде нет. Переменная окружения переопределяет любой ключ: `[book] chapter_template` → `BOOK__CHAPTER_TEMPLATE`.

Секрет `OFFICE__JWT_SECRET` кладём только в `.env`. Docker compose передаёт его и в api, и в office, а адрес редактора для браузера `OFFICE__PUBLIC_URL` собирает из `OFFICE_PORT`. Оба порта открыты только на `127.0.0.1`, а api отвечает только на свои имена хоста (`[app] hosts`).

Плагины — папка `PLUGINS_DIR` в `.env`, по умолчанию `./plugins`. Compose монтирует её в api, путь в контейнере — `[plugins] root`.

Шрифты для office — папка `FONTS_DIR` в `.env`, по умолчанию `./deploy/fonts`. Compose монтирует её в api (`[fonts] root`) и в office, в его папку своих шрифтов. Сколько ждать office и Google Fonts — `[fonts] timeout`.

Библиотека — папка, внутри которой лежат книги, `LIBRARY_DIR` в `.env`, абсолютный путь; по умолчанию домашняя. Api видит её только на чтение и по тому же пути, что на хосте: поэтому ссылка из блока ведёт к книге и в приложении, и в файловом менеджере. Книги с другого диска: указать в `LIBRARY_DIR` общую для них папку.

Имя автора в комментариях и рецензировании — `[office] author`. Корзина книги — `[book] trash`, ожидание ответа office — `[office] timeout`, MCP-сервера — `[spelling] timeout`. Часовой пояс api берёт у хоста (`/etc/localtime`): по нему время в именах папок корзины и дата обращения к веб-странице.

Сайты, с которых подключают веб-страницы, — `[web]`: сколько ждать ответа и как api им представляется. Многие сайты отказывают тем, кто не похож на браузер, поэтому там строка браузера.

### Настройки книги

Самая нижняя кнопка слева. Они хранятся в самой книге, в `настройки.json`, и меняются в оболочке, а не в `config.toml`. Там же адрес MCP-сервера проверки орфографии из его окна.

Оформление ссылок — по какому правилу встают новые сноски и примеры в форме данных. Пока правило одно, ГОСТ Р 7.0.5–2008. Другое, например западное, добавляется записью в `STYLES` в `service/sources/styles.py`: название и функция, которая собирает сноску из данных источника. Уже вставленные сноски смена правила не трогает.

## Разработка

Плагины: стандарт и что ещё не сделано — в [PLUGINS.md](PLUGINS.md). Шаблоны «Научной статьи» после правки `templates.py` пересобирает `uv run python plugins/article-style/templates.py`.

`make check-code` — ruff и mypy в dev-контейнере, `make fix-code` — автоисправления ruff. Для IDE: `uv sync` создаст `.venv`.

Зависимости добавляем с точной версией: `uv add --bounds exact <пакет>`. Они живут в образе, поэтому после добавления: `make compose-build`.
